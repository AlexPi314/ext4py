# ext4py

`ext4py` — утилита командной строки для чтения файловой системы EXT4 из
raw-образов без монтирования. С её помощью можно просматривать каталоги,
получать сведения о файлах, извлекать отдельные файлы и сохранять каталоги
в архивы `tar.gz`.

Для работы достаточно стандартной библиотеки Python. Утилита открывает
образ только для чтения и не изменяет его содержимое.

## Требования и запуск

Требуется Python 3.10 или новее. Работа утилиты проверена в Linux.
Устанавливать дополнительные Python-пакеты не нужно.

Чтобы запустить утилиту из исходников, перейдите в каталог проекта:

```sh
python3 --version
python3 ext4py --help
./ext4py disk.raw ls /
./ext4py disk.raw ls -a /etc
```

Здесь и далее `disk.raw` обозначает путь к образу EXT4, а `/etc` и
`/home/student` — пути внутри этого образа. Замените их на пути, которые
есть в вашем образе. Если подходящего образа нет, его можно
[создать для проверки](tests/README.md#создание-тестового-образа).

Если вы хотите вызывать `ext4py` из любого каталога, установите её в домашний
каталог и добавьте каталог с командой в `PATH`:

```sh
python3 scripts/install.py --prefix "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
ext4py disk.raw ls /
```

Для такой установки не нужны права администратора. Чтобы команда оставалась
доступна в новых сеансах терминала, добавьте строку с `export PATH` в файл
настройки вашей оболочки.

Установщик копирует модули программы и создаёт файл для её запуска. Если
по выбранному пути уже есть установка, он завершится с ошибкой. Чтобы удалить
установку из примера выше, удалите файл `$HOME/.local/bin/ext4py` и каталог
`$HOME/.local/lib/ext4py`. Подробнее о выборе каталога установки —
в [инструкции к скриптам](scripts/README.md).

Также утилиту можно запустить как модуль из корня проекта:

```sh
PYTHONPATH=src python3 -m ext4py --help
```

## Команды

```text
ext4py [--offset БАЙТЫ] ОБРАЗ ls [-a] [ПУТЬ]
ext4py [--offset БАЙТЫ] ОБРАЗ cat ФАЙЛ
ext4py [--offset БАЙТЫ] ОБРАЗ cp ФАЙЛ
ext4py [--offset БАЙТЫ] ОБРАЗ tar КАТАЛОГ
```

Указывайте абсолютные пути внутри образа, используя `/` как разделитель.
Для `ls` путь можно опустить: в этом случае команда покажет корневой каталог.
Для остальных команд путь обязателен. Параметр `--offset` указывается перед
именем образа.

В примерах ниже используется установленная команда `ext4py`. Если вы работаете
из каталога исходников без установки, используйте `./ext4py`.

| Команда | Что делает |
| --- | --- |
| `ls /` | Показывает имя, размер в байтах, время изменения в UTC и тип каждого объекта |
| `ls -a /etc` | Дополнительно показывает скрытые имена и записи `.` и `..` |
| `cat /etc/hostname` | Выводит содержимое файла в stdout без перекодирования |
| `cp /etc/hostname` | Сохраняет файл под именем `hostname` в текущем каталоге |
| `tar /home/student` | Сохраняет каталог в архив `student.tar.gz` в текущем каталоге |

Например:

```sh
ext4py disk.raw ls /etc
ext4py disk.raw cat /etc/hostname > hostname.txt
ext4py disk.raw cp /etc/hostname
ext4py disk.raw tar /home/student
```

Каждая команда принимает один путь. Поиск по шаблонам, например `*`,
не поддерживается. Команда `ls` сортирует записи по байтам имён, поэтому
порядок не зависит от настроек языка системы. Для символьных ссылок она
также показывает путь, на который указывает ссылка.

Справка доступна через `-h` или `--help`, в том числе для отдельных команд.
Чтобы узнать версию программы, выполните `ext4py --version`.

## Сохранение файлов и архивов

Команды `cp` и `tar` сохраняют результат в текущем каталоге. Чтобы сохранить
его в другом месте, сначала перейдите в нужный каталог. При копировании
сохраняется исходное имя файла, а архив получает имя каталога с окончанием
`.tar.gz`. Сжатие gzip используется всегда.

Если путь, переданный команде `cp`, ведёт через символьную ссылку, программа
скопирует содержимое целевого файла. Права доступа и владелец новой копии
определяются операционной системой, в которой запущена утилита.

Команда `tar` также следует по ссылке, если она указана в пути к извлекаемому
каталогу. Однако ссылки внутри этого каталога записываются в архив как ссылки,
без обхода их целей. Жёсткие ссылки на обычные файлы тоже сохраняются.
В архив входят сам выбранный каталог, его скрытые объекты и пустые каталоги.
При архивировании корня `/` верхний каталог в архиве получает имя `root`.

Архив сохраняет права доступа, владельцев и время изменения объектов.
FIFO и файлы устройств записываются только как заголовки архива: соответствующие
объекты в системе, где запущена утилита, не создаются. Если в каталоге есть
сокет, архивирование завершится с ошибкой. Содержимое разреженных файлов
сохраняется, но в архиве они занимают место как обычные файлы.

Программа не перезаписывает существующие файлы и символьные ссылки.
Результат сначала записывается во временный файл и становится доступен под
окончательным именем только после успешного завершения записи. При ошибке
временный файл удаляется. Для этого способа сохранения файловая система,
в которую вы извлекаете данные, должна поддерживать жёсткие ссылки.

Команда `cat` передаёт данные непосредственно в stdout. Если во время чтения
произойдёт ошибка, часть содержимого уже может оказаться в выходном потоке.
Сообщения об ошибках и сохранении файлов выводятся отдельно, в stderr,
поэтому они не попадают в содержимое файла.

Программа возвращает следующие коды завершения:

| Код | Значение |
| --- | --- |
| `0` | Команда выполнена успешно |
| `1` | Ошибка чтения или сохранения данных либо закрытие выходного канала |
| `2` | Неверные аргументы командной строки |
| `130` | Выполнение прервано с клавиатуры |

## Чтение из stdin и смещение раздела

Вместо имени образа можно указать `-`, чтобы прочитать его из стандартного
ввода. Например:

```sh
cat disk.raw | ext4py - ls /
cat disk.raw | ext4py - cp /etc/hostname
cat disk.raw | ext4py - tar /etc
```

Перед обработкой программа полностью сохраняет входной поток во временный
файл. Поэтому результат появится только после завершения передачи, а для
временного файла потребуется свободное место размером с образ. После работы
программы этот файл удаляется автоматически. Каталог для временных файлов
можно выбрать с помощью переменной окружения `TMPDIR`.

Если raw-образ содержит только файловую систему EXT4, смещение указывать
не нужно. Если это образ целого диска, укажите начало раздела EXT4 в байтах
через `--offset`. Программа не определяет разделы по таблицам MBR и GPT.
Например, для раздела, который начинается с сектора 2048 при размере сектора
512 байт, смещение составит `2048 × 512 = 1048576` байт:

```sh
ext4py --offset 1048576 disk.raw ls /
cat disk.raw | ext4py --offset 0x100000 - cat /etc/hostname
```

Смещение можно записать десятичным числом или в шестнадцатеричном виде
с префиксом `0x`.

## Поддержка и ограничения

Работайте с образом, полученным после корректного завершения работы файловой
системы, или с её согласованным снимком. Если данные зашифрованы либо находятся
в логическом томе, сначала подготовьте raw-образ EXT4 внешними средствами.

Утилита поддерживает обычные файлы, каталоги, жёсткие и символьные ссылки,
а также разреженные файлы. Образы с `meta_bg`, `bigalloc`, `inline_data`,
шифрованием или `casefold` отклоняются с сообщением об ошибке. Восстановление
журнала, удалённых файлов и повреждённых структур не поддерживается.
Программа также не выполняет полную проверку целостности файловой системы.

При обработке каталогов и создании архива расход памяти зависит от числа
объектов. Подробное описание поддерживаемых возможностей и архитектуры
приведено в [отчёте](docs/отчёт.docx).

## Проверка

Чтобы запустить проверки и измерить покрытие кода, выполните из корня проекта:

```sh
make check
make coverage
```

Тесты используют стандартный модуль `unittest`. Для интеграционных проверок
нужен `mke2fs` из e2fsprogs. Если он не установлен, соответствующая группа
тестов будет пропущена. Права администратора и монтирование образов не нужны.
Эти инструменты требуются только для тестов, а не для запуска утилиты.

Подробнее о [запуске тестов и создании тестового образа](tests/README.md)
и об [использовании вспомогательных скриптов](scripts/README.md).
